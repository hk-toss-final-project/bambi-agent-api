## ⚠️ 이 벤치마크가 측정하지 못하는 것

`run.py`는 `generate_report_content`를 **직접** 호출하고 근거 문서(P1·G1)를
데이터셋에서 그대로 주입한다. 따라서 위 변경 중 실제로 측정되는 것은 없다.

| 대상 | 측정 |
|---|---|
| 생성 프롬프트 · P1/G1 인용 | ✅ |
| 품질 재생성 루프 | ❌ `generate_report_content_with_quality`가 아니라 원본 함수를 호출 |
| 수집(Naver date+sim) | ❌ 경로를 지나지 않음 |
| 풀 검색 · 잡음 필터 | ❌ 경로를 지나지 않음 |
| 토픽 성격 판정(수집 창) | ❌ 경로를 지나지 않음 |

**이번 실행은 "생성 경로 회귀 없음" 확인에 그친다.** 오늘 변경의 효과 검증은
파이프라인(`load_context` → 생성) 전체를 도는 별도 벤치마크가 필요하다.

## 실행 메모

`run.py`가 dotenv를 로드하지 않아 `OPENAI_API_KEY`를 찾지 못했다
(`openai.OpenAIError: Missing credentials`). 형제 벤치마크
(`assistant_reformulation`, `wiki_builder`)에는 있는 처리가 이 파일에만 빠져
있었다.

위 2회 실행은 **측정 중 측정 도구를 바꾸지 않으려고** `.env`를 먼저 읽는 래퍼로
돌렸다. 결과 기록 후 `run.py`에 `load_dotenv(PROJECT_ROOT / ".env")`를 추가했고,
래퍼 없이 아래 명령으로 재실행해 **동일하게 10/10**을 확인했다.

```
uv run python bench/report_generation/run.py --confirm-cost
```

키를 읽는 위치만 달라지므로 프롬프트·모델·데이터셋에는 영향이 없다. 위 지연
수치는 그대로 유효하다.
