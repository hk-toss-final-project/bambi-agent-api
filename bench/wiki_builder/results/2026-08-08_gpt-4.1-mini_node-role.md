## 왜 만들었나

관심사 상위권이 사용자가 뉴스로 받아보고 싶은 대상이 아니었다. 2026-08-07 배포
데이터 실측:

| 사용자 | 상위 관심사에 섞인 파편 |
|---|---|
| mock-clipping-user | DBeaver Community(1.00), OpenWiki(0.88), Beekeeper Studio(0.81), pgAdmin 4(0.81), API 키 발급(0.81) |
| 28 | OpenWiki(0.90), DBeaver Community(0.85), DeepWiki(0.78), Cauchy·Kepler·Branko Grünbaum(0.68) |
| 40 | 기술노트with 알렉(0.83), AI 시대 개발을 위한 필수 IT 지식(0.67) |

`subtype`으로는 가를 수 없다 — DBeaver Community와 리튬황 배터리가 둘 다
`product`였다. 그래서 분류 시점에 노드가 **원문에서 맡은 역할**을 함께 판정하게
했다(`subject` / `tool` / `source` / `mention`).

## 고정 실패 2건

**`role-mention-historical-person`** — Kepler·Cauchy를 매번 `subject`로 판정한다.
프롬프트에 "정리·증명의 유래로 이름만 언급된 인물은 mention" 규칙을 넣었으나
바뀌지 않았다. 원문이 "Cauchy는 볼록 다면체의 강성을 증명했다"라고 서술해
모델이 실질적 대상으로 본다. 실측에서 이들 점수는 0.68로 중간권이라 도구
(0.85~0.90)만큼 위로 오지는 않는다. 더 강한 규칙은 기존 분류 회귀 위험이 있어
보류한다.

**`role-mixed-tools-and-subject`** — `제텔카스텐`이 매번 추출되지 않는다. 역할
판정 문제가 아니라 노드 추출 문제다.

## 실행 변동 (제 변경과 무관)

3회 반복에서 결과가 흔들린 케이스 3건은 **모두 "노드가 안 뽑힘"**이 사유다.

| 케이스 | 회차별 | 흔들린 사유 |
|---|---|---|
| group-profile | FAIL→PASS→PASS | 리센느 subtype |
| role-tool-is-subject-when-reviewed | PASS→FAIL→PASS | DBeaver Community 미추출 |
| role-product-that-is-newsworthy | PASS→PASS→FAIL | 셔틀 현상 미추출 |

`group-profile`은 2회차에 실패해 회귀로 의심했으나 3·4회차 통과로 **실행 변동**임이
확인됐다. 역할 판정으로 인한 회귀는 없다.

흔들림의 방향이 "진짜 관심사를 놓치는 쪽"이라는 점은 남는 위험이다. 다만
`interest_subject`는 한 번이라도 주제였으면 유지되므로, 같은 주제로 글을 두 번
이상 저장하면 회복된다. 노출되는 경우는 **글 하나만 저장된 주제**다. 추출 변동
자체는 이번 변경 이전부터 있던 성질이라 별도 과제로 둔다.

## 채점 기준 변경 기록

1회차는 역할이 정답과 **정확히 일치**해야 통과로 채점했다. 목적과 어긋나
`OpenWiki=mention`(기대 tool), `API 키 발급` 미추출이 실패로 잡혔다 — 둘 다
관심 후보에서 빠지므로 의도한 결과다.

2회차부터 `subject`인지 아닌지만 본다.

- `subject` 기대 → 추출돼야 하고 `subject`여야 한다 (놓치면 관심사를 잃는다)
- 비-`subject` 기대 → `subject`만 아니면 통과 (미추출도 통과)

결과를 본 뒤 기준을 바꾼 것이라 사용자 승인 후 적용했다. 케이스는 제거하지
않았고 실패도 그대로 기록한다.

## 남은 것

- 기존 위키는 재빌드해야 판정이 붙는다. 표시가 없는 노드는 그대로 통과시키므로
  당장 관심사가 사라지지는 않지만, 파편도 그대로 남는다.
- 역사적 인물 판정과 노드 추출 변동은 별도 과제.
