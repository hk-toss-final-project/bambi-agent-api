# bench/ — LLM 기능 벤치마크

LLM을 호출하는 기능의 품질을 측정하는 벤치마크 디렉터리입니다.
`tests/`와 달리 **실제 LLM API를 호출**하므로 비용이 발생하고 결과가 비결정적입니다.
CI나 일반 개발 흐름에서 자동 실행하지 않고, 필요할 때 명시적으로 실행합니다.

자세한 규칙은 루트 `AGENTS.md`의 "8. LLM 기능 벤치마크"를 따릅니다.

## 디렉터리 구조

기능 하나당 디렉터리 하나를 만듭니다.

```
bench/
  <기능이름>/                  # 예: intent_classify, web_search_agent
    dataset.jsonl              # 평가 케이스 (입력 + 기대 결과/채점 기준)
    run.py                     # 벤치마크 실행 스크립트
    results/
      2026-07-10_gpt-5.4.md    # 실행 결과 기록 (날짜_모델명.md)
```

## dataset.jsonl 형식

한 줄에 케이스 하나씩 JSON으로 작성합니다.

```jsonl
{"id": "001", "input": "내일 서울 날씨 알려줘", "expected": {"intent": "weather"}, "note": "정상 케이스"}
{"id": "002", "input": "날씨... 아니다 뉴스 보여줘", "expected": {"intent": "news"}, "note": "의도 번복 케이스"}
```

- `id`: 케이스 식별자. 결과 기록에서 케이스별 성패를 추적하는 데 사용합니다.
- `input`: 기능에 넣을 입력.
- `expected`: 기대 결과 또는 채점 기준.
- `note`: 이 케이스가 검증하려는 것 (선택).
- 최소 10개 이상으로 시작하고, 정상 케이스뿐 아니라 경계/실패 케이스(모호한 입력, 긴 입력, 한국어/영어 혼용 등)를 포함합니다.

## 실행

```bash
uv run python bench/<기능이름>/run.py
```

- 실행 전에 케이스 수 × 예상 토큰으로 대략적 비용을 확인합니다.
- `run.py`는 실행이 끝나면 `results/`에 결과 파일을 남깁니다.

## 결과 기록 (results/*.md)

결과 파일에는 다음을 반드시 포함합니다.

- 실행 날짜, 모델명·버전
- 프롬프트 버전 (또는 커밋 해시)
- 케이스별 성공/실패
- 집계 지표 (정확도 등), 평균 지연시간, 토큰 사용량(비용)
- 이전 결과와의 비교 (회귀가 있으면 그대로 기록)

## 금지 사항

- 잘 나온 결과만 골라 기록하지 않습니다.
- 실패하는 케이스를 데이터셋에서 임의로 제거하지 않습니다. 데이터셋 변경은 사용자 승인 후에만 합니다.
- 벤치마크 결과를 좋게 만들 목적으로 채점 기준을 완화하지 않습니다.
